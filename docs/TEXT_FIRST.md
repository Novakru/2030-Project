## 设计选择

采用 mattpocock 的 codebase-design、Design It Twice 和 research 工作流。三个方案分别优化最小提取入口、库迭代扩展能力、默认文本文件使用方式；组合为文本隔离入口、领域验证器和版本化库演化。研究依据见 [一手资料记录](research/text_and_libraries.md)。

提取模块依赖原文和操作合同；真实模型是可注入的外部依赖，测试使用明确的替身。文件和 SQLite 可在本地验证。领域包拥有语义、导出和风险规则；编排不直接假定化学字段。器材族只负责相似用途索引，参数范围不取并集，缺失条件不能变成可替换证明。

原文没有写出的数量不从 ORD 补齐。按用户的新要求，默认输出 [扩展 XDL](EXTENDED_XDL.md)：新动作由 agent 补充声明式原子操作合同；缺参用 `__NOT_REPORTED__` 等标识保存，可以作为完整表达的 silver 正例。工具仍遗漏动作、虚构参数或输出非法格式时才进入未完成队列。生成数量不能替代事实忠实性，也不用额外作者 XDL 或构造场景凑纯文本数量。

Goal 后端仍持有旧的 `usageLimited` 目标，拒绝新建；本文件记录本轮任务，不把未完成的旧目标误标为完成。
