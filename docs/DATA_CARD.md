# 数据含义与边界

## 三种不同的数据

`data/raw/reactions.parquet` 保存固定版本 ORD 的真实原始反应及规范化字段。上游 Parquet 文件、SHA256、版本和许可见 `data/sources.lock.json`、`data/upstream/`。`data/raw/protocols/` 是选中流程的逐条完整 raw 文件。

`data/positives.jsonl` 和 `data/xdl/positive/` 是有实测产率 >30% 的原始反应的 XDL 表达。`extraction.method` 指明文本提取还是结构化重建；结构化重建只覆盖已准备投料与反应保持阶段，不能当作完整后处理。原料组内顺序没有被上游定义时，不声称组内逐项顺序具有实验依据。

`data/negatives.jsonl` 是从这些真实来源父流程派生的研究候选。父流程尚为 silver，故 `benchmark_eligible=false`。`data/controls/` 是独立手写的规则控制场景，不是 ORD 实验，也不充当 gold 父流程。两类样例在所有报告中分别统计。

`data/sop/` 补充 B2/B3/B5，共 17 个父流程片段或场景、34 个错误变体。B5 的 10 组原文配方具有不同的实际投料量，来源和文本行号在 `libraries/sop_recipes.yaml`；保留原 PDF、提取文本及两者 SHA256。仅保留来源写明的浓酸限定，除 USGS 明确给出的 96% 外，不填造 98% 等数值。`about` 保持近似，定容补水量不由体积相减推算。

B2 的 12 条来自同一个 DMSO 解冻实例，B3 的 12 条来自 6 种溶剂与 2 类点火源组合。它们标为 `instantiated_sop`，30 C 等参数是来源约束范围内的构造值，非原文条件、非独立原始实验。纯物质、开放容器、空气和暴露界面等假设在每条 `construction.assumptions` 中明确列出。B2 指体相达到热平衡后的液态要求，不排除瞬时过冷；B3 判定点火风险，不声称已发生火灾。24 个生成实例与 213 条直接来源派生候选分别统计，控制样例另计。统一计数见 `data/dataset.json`。

SOP 预装物料放在 `initial_contents`；未知体积保持 null，不补造一条有定量的 Add。缓慢加料、搅拌、冷却、定容等未量化指令保留在 `unresolved_instructions`，同时导出为 XDL 注释。它们是可用于风险研究的流程片段，尚不能作为完整设备指令执行；点火条件同样依赖 JSON 侧车上下文。此分区全部 `benchmark_eligible=false`，人工审核暂缓。

## 正确性分层

自动检查包括：来源哈希、字段保真、原文证据子串、显式数字及单位、温度/时长比较、本项目 XDL 2 子集 XSD、规则违规、去重、补丁复原和集合划分。

结构化字段原样附到步骤上的用量检查仅证明没有丢失字段，不是独立抽取准确率。不能把这些检查称为实机编译、实验重现或完整可行性证明。所有待核对事项均保留在 `quality` 与 `crosscheck` 中。`strict_gold=0` 时表示确实还未满足规范的 gold 条件。

文本提取快照保留原始 API 返回的试剂别名。新增的独立用量核对只读取该别名相邻的原文数值，支持质量、体积、物质的量及基于来源 SMILES 的分子量换算；歧义别名、范围、浓度、mol% 和跨试剂数量不自动通过。匹配必须有独立数量落在 ±10% 内，不能忽略另一个精确数值的冲突。数字核对不等于化学实体名称匹配已经获得独立人工确认。

对印刷时明显粗略舍入的值，不把它机械地判成矛盾：只有另一个独立数量在 ±10% 内一致、且粗略值在最后一位数字的舍入区间内兼容，才确认一致；只有粗略值时仍为 unknown。分散剂、溶液或水合状态不明时，不从混合物质量推断纯化合物的物质的量。

`data/publications/` 是独立的 Science 2022 作者原始 XDL 参考语料。保留成功分区与仅翻译分区，不把后者标为实验成功。XML 大小写与能唯一匹配已声明名称的尾随空格修复保留原件、差异与 SHA256；未知化学品、缺失器材和占位引用不猜测补全。参考副本的静态检查不改变其 `benchmark_eligible=false`，也不混入 ORD 正样本或 gold 数量。

`schemas/xdl2_subset.xsd` 来自公开 XDL 2 步骤表，是明确标注的本项目子集，不是 Cronin 官方完整 schema。内部 `Atmosphere(mode=environment)` 导出为上下文注释，不捏造吹扫操作；色谱导出到公开的 `RunColumn` 占位步骤，其内部细节未被自动补全。任何样本都没有连接或驱动实物设备。

`data/publications/platform_validation.jsonl` 增加原配套平台的类型解析、原图编译与内置检查结果。编译器来自同一论文的 supporting-files 归档，源码保持原样；XDL 核心版本为 0.5.0，ChemputerXDL 为 1.0.0，适配和依赖版本明确记录。单一 Synthesis 的外层 XDL 包装和带明确单位的属性别名可以机械适配，副本与更改列表保留。对省略 pid 的 Async 提供来源和路径决定的稳定 ID，避免上游默认随机 UUID 影响复现；已声明的进程 ID 及 Await 等待关系不变。缺图、无支持步骤、未知质量/体积或检查失败均不强行通过。`platform_positives.jsonl` 仅包含编译通过条目，作者成功分区与仅翻译分区仍然区分，不等价于本项目的 gold、实机复现或全约束安全证明。

## 标签

- `hard`：违反显式声明的规则约束，不代表已观察到实验事故。
- `soft`：条件扰动假设；`feasible=null`、`p_infeasible=null`，不伪造失败概率。
- `real`：HTE 观测产率 <5%，只说明低产率。HTE 的 >30% 记录作为成功观测；中间区间不进模型。

HTE 单行产率不自动提供 C1–C6 的因果归因。未经按子类验证，研究基线始终不具备 judge 准入资格。

产率只取一个明确目标产物的无冲突百分比测量，记录 `yield_evidence` 中的原始字段路径。明确标为副产物的记录不参与目标产率；多个目标、无目标标记的多产物、不同分析方法或重复测量给出不同产率时不自动选最大值。不明确或超出 0–100% 的值不产生成功/失败标签。HTE 与成功条件过滤共用这一策略，零投料成分按缺席处理。

`data/hte/contrasts.jsonl` 保存成功与低产率实验之间的单因素记录对照。目标产物、研究、输入顺序、载体溶剂、非目标数量、器材、步骤说明、分析方法及其他原始条件均保持一致。所有匹配重复实验都进入阈值判断；不是从互相矛盾的重复实验中挑选高低产率。该数据不混入合成扰动样例，不建立排除所有未记录混杂因素的因果结论，也不把“见过的溶剂”对照冒充 C1 的“该反应类别从未出现”条件。

## 风险判定的科学限制

混合溶剂与含溶质体系的凝固点需要相图或实测，不能取组分熔点最大值。加热温度超过闪点也不足以单独断言起火；必须有明确点火和暴露条件。热板温度范围不直接等于液体温控范围。未知、未核实的器材参数不参与 hard 判定。

用户要求当前优先构造数据、暂缓人工审核。带原始厂家出处并已核对的器材事实可以用于 `source_reviewed_provisional` 研究约束；`verified=false` 及 `benchmark_eligible=false` 保持明确。A2 注入的控制器请求与样品温度分别存储，不根据样品温度猜测原始热板设定值。

`data/native_negatives.jsonl` 是独立的作者原生格式分区，D2 针对物料输入依赖：源图明确目标容器初始体积为零，原程序只有一个进料语句，其后有蒸发操作。删除该语句后物料输入消失。该验证不等于原生程序的全部化学或器材规则已被重新编译检查，也没有观察负例的实验结果。普通 `Filter` 后跟 `WashSolid` 不足以推出过滤必需，因为上游 `WashSolid` 本身包含过滤。

同一类可以命中多个具体条款；单故障要求只命中一个风险子类。一个语义上的换料或顺序交换可以对应多个 RFC 6902 补丁操作；更新派生 XML 与质量字段不增加故障数量。
