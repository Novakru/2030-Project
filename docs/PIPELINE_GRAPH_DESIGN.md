## 目标

从原始实验文字识别物料、状态、操作、条件和依赖，再由程序编译为扩展 XDL。图必须区分“向悬浮液加入某物”与“把悬浮液加入某处”，并能追踪 mixture、solution、residue、filtrate 等跨句引用。

建议将现有 extractor 改为语义解析前端，一次提出有原文依据的事实、角色、共指及关系候选；程序负责构图、状态更新与约束检查。独立核对仍直接对照原文。不先自由改写一遍步骤文字再交给另一个提取器。事实、证据和图使用同一套稳定 ID，不维护两份互相矛盾的材料与用量表。

## 图的合同

物料流部分是有向双部图：`物料状态 → 操作 → 新物料状态`。节点与边描述以下信息：

| 对象 | 最小内容 | 例子 |
|---|---|---|
| MaterialState | 稳定 ID、物料身份／组成事实引用、已报告形态、来源类别、证据 | 加料前的悬浮液、搅拌后的混合物、滤饼 |
| Operation | 稳定 ID、原文操作表达、带角色的输入、输出状态、参数事实引用、证据 | Add 的加入物与接收物；Filter 的滤饼与滤液 |
| Material flow | 状态、操作、角色、证据／派生依据 | added_material、receiver、retained_solid、filtrate |
| Temporal constraint | 两个操作、关系、证据 | precedes、same_interval、during；未报告的顺序不补齐 |
| Equipment use | 操作、设备／逻辑位置引用、角色、状态 | 作用设备、容器、来源、去向；未知设备不创建型号或子型 |
| Fact | 原文字面、语义值、单位、状态、主体与范围、证据 | 25.4 g 属于悬浮液组分，18 ml 属于加入份额 |

节点 ID 区分身份与状态：同一物料经加料、过滤等操作后使用新的 state ID，并保存 lineage；不会反复覆盖一个名叫 mixture 的对象。状态版本只描述流程来源，不推断反应后化学组成或数量。

时序、并发和设备关系单独存放，不把所有边都当成先后关系。物料流的一个实例通常为 DAG；明确的重复或条件循环使用有边界的控制块，其 body 可为 DAG。未报告次数／停止条件保留未知；不把任意循环强行展开，也不把所有步骤串行化。

## 三种证据来源必须区分

1. `reported_action`：原文明确写出的实验动作。
2. `reported_initial_state`：原文描述已经存在的混合物及组成，没有写出制备动作。
3. `compiler_derived_initialization`：为满足某个目标平台的输入要求，由确定性规则生成的初始化步骤。它不是原文动作，也不是 agent 猜测的实验事实。

规则只允许从明确的组成关系生成必要的配置／加入指令。规则不得推断溶解、搅拌、加热、加料顺序、设备规格、混合后总体积或 15% 的质量／体积基准。生成的步骤保留 `derived_from` 事实引用与编译策略版本，写于配套 JSON，不通过扩展 XML 属性混入 provenance。

## 对 XDL 编译的约束

默认的保真表示保留初始状态作为前置条件；原文动作从向其加入溶液开始。是否将初始状态物化为 XDL 的初始化步骤，是显式编译配置，而不是提取器自行决定的实验事实。

启用初始化时，可由已报告组成产生加入 A、B 和乙醇的计划；它们构成“全部先于溶液滴加”的依赖组，不声称三者的顺序。若所选 XDL／平台必须给出线性顺序，程序不能随机选择并宣称与原文等价：需要平台批准的确定性策略及派生记录，或保留为未解决的执行条件。

保真数据中可以保留未知值，但不能因此宣称已具备可执行性。未给出的接收容器类型、位置与额定参数不可由编译器补造。目标 XDL 不能容纳的初始状态或并发结构应明确报告表达限制；不能用任意 XML 属性伪装支持。

XDL 仍保留既有 XML 结构；只使用已登记操作／器材及其参数合同。图、规范 ID、证据、组成、派生计划和范围信息保留于配套 JSON。禁止 `subject_<entity_id>_mass` 等随样例变化的属性；当前编译器的自动兜底扩展应在下一实现轮次替换为明确合同。

官方 XDL 文档已经提供可选的 `Prep`、`Reaction`、`Workup`、`Purification` 分区，因此经批准的初始化指令可以放入既有 `Prep`，无需发明图形 XML 语法。但这些分区本身不能证明初始化来自原文，也不表达“未知加料顺序”。官方 Add 的 `reagent` 是加入物，`vessel` 是目标容器；receiver 状态到容器的定位应由图与设备绑定解析，不能再把 receiver 作为第二个 reagent。[文件结构](https://croningroup.gitlab.io/chemputer/xdl/standard/xdl_file_structure.html)、[步骤合同](https://croningroup.gitlab.io/chemputer/xdl/standard/full_steps_specification.html)

## Agent 与程序职责

| 角色 | 应做 | 不应做 |
|---|---|---|
| Pipeline 梳理 agent | 读全文；提出状态、操作、角色、范围、共指、分支与证据 | 为使步骤完整而发明原文未给的制备条件 |
| 图校验程序 | 检查引用、类型、角色合同、状态 lineage、用量归属、覆盖与时序一致性 | 以合法 JSON／无环来证明科学正确 |
| 独立核对 agent | 原文对照图，检查遗漏／猜测、初始状态误写动作、输入接收物反转、滤饼滤液接错等 | 仅检查 planner 的文字摘要，或自由重写整图 |
| 库维护 agent | 为新操作／器材提出语义及映射；动作包含角色、前置条件及状态效果 | 根据名称相似合并新语义，或改写原文事实 |
| 编译器和独立检查器 | 按合同输出 XDL，再独立读取 XML 对照图和事实 | 依赖任意动态属性弥补角色缺失 |

建议正常流程保持两次模型调用：语义关系提案一次，独立核对一次；格式与语义修复共一次预算。库维护仍按整批处理。程序化构图、状态更新、时间一致性与编译检查均不调用模型。这是预算设计，不是已经测得的效果或耗时保证。

## 从图格式落实为可运行的系统

以下为下一版本的实施方案，尚未实现。现有 `facts.py` 的 `Event.participant_ids` 没有输入角色；`fact_xdl.py` 的 Add 分支遍历参与物；`atomic_operations.yaml` 的前置条件与效果主要是文字，当前提取—编译主路径没有据此执行状态更新。只换提示词或把输出改成 JSON 图，无法补上这些实现缺口。

建议采用“语义解析前端 + 图构建与约束检查 + 状态解释 + XDL 后端”：

```mermaid
flowchart TD
  T[原文快照与证据位置] --> P[模型：事实、角色、共指和时间关系候选]
  P --> G[程序：类型检查、确定性构图、状态版本]
  G --> C[程序：时序约束与操作语义检查]
  C --> V[模型：原文对照，提出局部缺失或错误]
  V --> R[必要时一次局部修复，重新运行同一检查]
  V --> S[冻结语义图；保留未知和未解析项]
  R --> S
  S --> B[器材绑定、初始化及目标执行计划]
  B --> X[XDL 编译与独立语义保留检查]
```

### 1. 证据层：稳定位置先于语义归属

冻结原文，保留字符位置、句段顺序和精确片段。数字与单位识别只产生待核查候选，不将 NMR 数字等自动当作过程参数。数量同时存原文字面与解析值，例如 `1/2 hour`、`0°-5° C.`、`4-M`；能确定的转换由显式数值解析规则完成，不能解析的已报告文字保留为 `unparsed`，不误记为来源缺参。

证据定位必须区分完整物料名与另一个物料名中的子串，防止将 ethanol 定位进 methanol；支持重复出现的位置和嵌套片段。原文次序始终保留为元信息，但不自动成为所有操作的严格先后边。

### 2. 语义解析：模型提案，程序接纳

模型提出动作表达、物料提及、数量归属、作用对象、receiver、共指、初始状态和时间关系，并引用证据 ID。它不输出最终 XDL，也不被要求猜出完整实验步骤。一个真正有歧义的引用可以保留少量候选；程序仅在语义／时间约束排除其他候选后唯一绑定。仍有多个自洽候选时保留 `ambiguous`，不以模型自报置信度直接决定。

图构建器维护物料身份、份额及状态版本，生成节点和显式连接。未出现的状态节点可以作为操作输出由规则生成，但必须标记规则来源，不能为其发明体积、化学组成或收集动作。LLM 格式正确只表示提案可读；图自洽也不能证明提取忠实。

### 3. 时序与因果：分别建模，再检查一致性

| 关系 | 合法依据 | 不允许的替代 |
|---|---|---|
| before / during / overlaps / same_interval | 明确的语言范围、事件引用、已报告条件 | 看到 while 就将两个动作起止时间设为相同 |
| material_dependency | 经共指确认的上一步输出是本步输入 | 将相邻句子全部连成物料依赖 |
| enables / guard | 原文说明的执行前置条件或版本化操作规则 | 因 A 在 B 前面就声称 A 导致 B |
| source_order | 原文字符位置与段落顺序 | 将叙述顺序直接当成执行总序 |

时间检查先实现有向先后关系、区间起止约束和已报告时长的一致性。能表达为简单时间网络的部分使用差分约束；缺失时长保持未定，不求一套看似完整的具体时间表。循环保留作用域和明确次数／终止条件；不让展开循环改变原文结构。

冲突必须返回涉及的边、事实 ID、来源和规则，而不是悄悄删除一条约束。第一版不引入生产调度优化器；只有确需互斥资源或复杂择一约束时再评估求解器。时间自洽不能验证语言理解正确；原文自身也可能矛盾，不能强制“修正”原文。

简单时间网络适用于闭区间差分约束的合取；它不自动解决全部 Allen 关系、严格不等式、析取选择或资源分配。具体适用范围与一手依据见[时序约束调研](research/WORKFLOW_STATE_PLANNING.md#implementable-hybrid-parsing-and-temporal-constraints)。

### 4. 状态解释器：运行操作的抽象语义

将操作合同的角色、前置条件与状态效果转成可检查的数据，而不只保存自然语言描述。第一版只提供少量通用的状态规则，例如引入物料份额、位置转移、保持物料来源的处理、分离产生支路、观察不改变物料；规则名称和参数通过受控解释器运行，不让维护 agent 任意生成可执行 Python。

- Add 消耗“加入份额”和 receiver 的状态引用，产生新 receiver 状态；溶液中的溶质与溶剂不是另外两次加料。
- Transfer 改变已报告的位置／份额关系；未知数量不形成精确库存。
- Filter 建立滤饼／滤液两个支路，后续共指决定使用哪一支；未知支路数量和去向继续未知。
- Mix、Heat 等保留处理来源与条件；不预测反应产物，不自动守恒体积，不将祖先组成等同于反应后的实际组成。
- 设备可以是动作的作用对象，也可以是使用的器材／位置，不能一律当作试剂输入。

库演化需同时提交角色与状态规则引用。若现有规则不能无损表达新语义，保留有证据的新事件和未解析效果，进入合同演化；不能为了构成自洽图而将新操作强行映射到 Add 或 Mix。

### 5. 两个编译阶段，共用一个语义事实源

语义阶段输出 `PipelineGraph` 和问题清单；不依赖具体器材型号或 XDL 语法，也不等待所有执行参数补全。执行阶段另选硬件、目标语言合同及初始化策略，产生执行计划，再输出 XDL。

每个执行步骤记录到原文动作或派生规则的映射。XDL 中因目标平台默认值而增加的含义必须另行核查。输出的原文保留图始终不被执行补全覆盖；编译器必须明确报告无法表达或仍缺执行条件的部分。

建议保持两个小的公共接口，其内部算法可以替换：

```python
analysis = pipeline.resolve(document, proposal, operation_contracts)
artifact = xdl.compile(analysis.graph, target_profile)
```

`resolve` 返回 graph、issues、unresolved 和来源依据；`compile` 返回 XML、配套 JSON、源动作／派生规则映射及编译问题。现有 Registry、RunStore、审计数据库继续复用。图合同、构图／状态解释、语义解析调用、XDL 后端各自集中实现；替换现有平铺参与物和动态属性兜底，不长期保留两套生产主路径。

### 6. 能力如何迭代，而非只累积提示词

先建立少量经人工确认、覆盖典型结构的原文—图对与最小对照句：加入／接收反转、初始状态／显式制备、滤饼／滤液、倒叙、并发、重复和条件终止。规则检查及状态解释负责确定性约束；检索少量已确认的同结构图例辅助模型理解。未经人工确认的 silver 输出不自动成为范例真值。

稳定积累专家修正后，才评估是否需要专门训练共指／关系解析器或微调模型；训练目标是图角色、引用、关系和证据，不只模仿 XML。提示与示例优化在离线开发集进行，不能在生产批次中自动改变验收标准或改写代码。

复杂领域模型是可选适配，而不是基本图合同的前置条件。第一阶段复用 Python、Pydantic、现有 YAML 合同与回执，不引入第二套多 agent 运行时、图数据库或自建图神经网络。

## 下一实现轮次的最小验证

先用已保存模型回执和人工确认的小图验证通用语义，不再为本批追加提取调用：

- `add A to B` 与 `add B to A`：只改变加入物与接收物；数量不串绑。
- 现成 suspension 与明确 `prepare ... by ...`：仅后一种具有来源动作。
- 初始混合物、跨句 mixture／solution、混合后状态：ID 可追踪且不重复加料。
- 过滤后处理 residue 与 filtrate：后续支路分别连接，不混为同一个样品。
- `heat while stirring`、并行制备 A/B、重复洗涤：保持并发／依赖／次数合同。
- equipment 被 purged／cleaned：作为动作的作用对象，不塞进物料 participant。
- 分数时长、带度符号的区间、`4-M` 浓度：保留原文字面与可验证语义值。
- microreactor：保留标准子型，不凭名称推断连续流。
- 未知原子操作：能够经角色、前置条件、状态效果的库演化进入系统。

评价至少分别报告实体／数量覆盖、角色与共指正确率、物料流边及时间关系正确率、无依据新增动作、图到 XML 的保留率、专家确认程度。图看起来合理和 XML 能解析均不足以通过验收。

离线回执重放只验证程序对已知输入的行为，不能被当成新模型提取准确率。旧五条作为开发回归；新版本冻结后按事先固定的预算运行一批五条，逐来源保存完整或部分图。源文缺参、提案结构错误、图冲突、未知库语义及 XDL 表达缺口分别统计；五条样例不能覆盖全部领域结构或证明批量泛化。

第一实施里程碑先验收“原文到图”：悬浮液的组成与状态、加料角色、后续物料流、过滤分支、时序和证据都正确。随后验收图到 XDL。若图层未通过，不通过改 XDL 模板制造端到端成功；若存在真实矛盾或多个自洽解释，保留问题供审计。

时序评价比较偏序所蕴含的可达关系，避免把 `A→B→C` 与增加冗余 `A→C` 的等价先后关系误判为不同流程；直接物料流及 enables 边仍按各自语义单独评分，不能将所有传递可达关系都当作原文明示的因果。节点对齐依据原文证据、类型和角色，不以模型生成的 ID 字面是否相同评分。同义改写应保持这些关系；交换 before/after、receiver/added_material 或 residue/filtrate 必须产生对应的图变化。

实施顺序为：确认图合同 → 替换现有平铺 participant 及动态属性兜底 → 离线证据验收 → 冻结新版本 → 一次整批真实验证。每批结束再讨论缺陷，不逐样例修改代码。
