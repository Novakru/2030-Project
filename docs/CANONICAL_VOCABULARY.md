# 规范概念与表述映射

Facts 保留原文名称、证据、事件与参数；XDL 使用具体规范操作和器材类型。库绑定与事实提取分开，不改数量、作用范围或错误引用。

| 文件 | 职责 |
|---|---|
| atomic_operations.yaml | 稳定操作 ID、名称、参数、前置条件、状态效果、能力要求 |
| operation_mappings.yaml | 精确表达映射、语义参数和旧名称迁移台账 |
| equipment.yaml | 规范类别、子型和配置声明 |
| equipment_mappings.yaml | 别名、型号归属和独立的条件替换 |

基库有 48 个动作／观察／条件／来源概念，10 个器材类别、22 个子型，不预设压缩数量。旧 204 名称、547 合同版本台账仍可追溯；新版不经过旧核心／扩展 IR 或数量适配器。旧 primitives、macros 和依赖代码已删除。

Mix 的 method 保留 stir／shake／vortex。Heat 与 Mix 同步是显式事件关系，组合词不能当作 Heat 的普通别名。剂量、时间、温度、容量保留来源、绑定和范围。型号及额定值属于实例配置，不推动公共词汇膨胀。

演化步骤：未知表达 → 对照已有概念 → 别名／参数变体／新语义提案 → 来源和类型检查 → 冻结事实见证 → 库事务 → 同一事实重新绑定。新操作需声明参数、前置条件、效果、能力；新子型需对照已有子型，类别确有新语义时可增加。别名必须有来源和往返见证，不能引入默认容量或压力。

别名表示同一概念；条件替换表示不同器材可能满足同一任务。替换需要独立物理检查及未知条件边界见证，缺容量、材料、范围、接口等条件时仍为 unknown。共享类别不足以建立替换。准入保持 representation_only／silver，专家仍需判断模型提出的语义。

每批版本写入 library_registry.json，下批通过 --registry 继承。两个库存文件分别统计规范事件和器材实例，并列出未解析项；次数和可表达性不等于通用最小集或科学认证。
