# 规范概念与表述映射

保存顺序为：原文提取 → 已登记表述解析 → 参数映射与组合展开 → 规范合同检查 → XDL。归一不调用模型、不补实验事实。

| 文件 | 职责 |
|---|---|
| `atomic_operations.yaml` | 稳定操作 ID、规范名称、参数、前置条件、状态效果与能力要求 |
| `operation_mappings.yaml` | 表述、适用上下文、参数转换、组合时序和精确来源合同映射 |
| `equipment.yaml` | 规范器材类别、标准子型和配置规则 |
| `equipment_mappings.yaml` | 器材别名、型号归属及独立的条件替换关系 |

当前目录有 48 个动作／观察／条件概念，以及 10 个器材类别、22 个标准子型。数量由复用能力和语义完整性决定，不预设压缩目标，也未证明达到通用最小集。

## 操作

操作身份使用 `operation_id`，如 `op.add`、`op.mix`；`op` 保存规范名称。Add 承载物料和多种独立用量，Mix 用 `method` 保留 stir／shake／vortex，Heat 保留能量输入及温度作用对象。更改显示名称或新增别名不改变语义合同哈希。

“加热并搅拌”展开为独立成员和 `same_interval` 时间关系，不能作为 Heat 的普通别名，也不把共享时长重复计算。观察、条件和物理动作具有不同 kind。

数值只按有依据的固定单位转换。质量不凭结构信息推算成物质的量。未知数值、定性描述及歧义保留明确状态和原文，不转成默认零或假定时长。

当前映射包含 204 个来源名称、547 个精确合同版本的整理结果。既有来源名称不是另一套公共操作库；合同不匹配时保持未解析，不仅凭同名或相似度合并。

## 器材

器材采用 `category_id`、`subtype_id`、`configuration` 三层。ReactionContainer 下的 Microreactor 与 RoundBottomFlask 是不同标准子型。微反应器归类后仍保留其身份，原文没有说明时不推断连续流。型号、容量、材料和接口保存在配置或来源参数中。

别名指向同一概念。条件替换单独维护，需检查明确关系与容量、材料、温控、混合和接口等需求，结果为 compatible／incompatible／unknown。同类器材不能直接视为可替换。

未知器材保留原文与未解析原因，不补默认子型。公共定义的新子型和替换关系目前仍需受控维护；智能体可自动登记观察、归入已有族、提出新族候选。

## 证据与演化

每条记录保留使用的规范合同、原始表述、字段绑定与转换规则。内部投影读取当前参数，不用历史副本覆盖编辑后的值。组合展开和 XML 往返保留信息及时间关系。

库维护角色优先提出映射或参数变化。新语义需要现有概念比较、声明式合同、来源证据及往返见证，通过程序检查后加入新的库快照；未知含义继续保留候选。合同准入只代表能够表达，不代表存在设备执行器。

`primitives.yaml`、`hardware.yaml`、`equipment_families.yaml`、`macros.yaml` 是提取及内部表示适配所需定义：分别保存核心字段、引用过的器材配置、分类和待证明的组合模板。最终样例以四份公共规范库为准。
